# 订单、付款单卡片加载优化（2026-09-28）

## 原因与修改

原页面在显示20张卡片前，使用 `allRows` 顺序下载全部历史记录。付款页面还同时下载全部订单、项目和供应商。付款旧列表序列化时逐条懒加载订单、收款单位及发票，形成大量数据库查询。

新增需要登录的 `/api/v1/workspace/orders` 和 `/api/v1/workspace/payments`：

- 默认每页20条，单次最多100条；项目、联系人、单号、付款状态在数据库筛选。
- 返回轻量项目/联系人选项及全部筛选结果的金额汇总；隐藏已结清仍不改变订单顶部汇总口径。
- 仅为当前页批量加载关联资料，付款卡片直接获得订单付款累计值和收款账户。
- 保留三栏筛选、卡片列数、关联单据和原编辑/打印入口。导出按需获取全部匹配记录。
- 筛选输入合并请求，取消过时请求并忽略迟到结果；返回列表时重新查询以反映编辑结果。
