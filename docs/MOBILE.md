# 手机工作台

## 本地入口与范围

- 手机端：`http://127.0.0.1:5050/m/`，Vue 3 + TypeScript + Vant，哈希路由。
- 电脑端：`http://127.0.0.1:5050/`，个人菜单增加“手机工作台”；手机“我的”可切换电脑版。
- 共用现有账号、JWT、字典和 `/api/v1`；模块入口根据账号已有菜单显示。
- 项目、订单、付款提供查询、详情、新增、编辑，支持项目→订单→付款关联。供应商和付款单位仅查询选择。
- 拍照、相册、文件上传，图片预览、文档打开；单文件前端限制 10 MB。失败可手动重试或移除失败任务，失败任务存在时不能提交业务表单。
- 本版本不包含删除、审批、离线录入、批量操作或材料/苗圃/系统管理迁移。

## 代码与构建

`frontend/src/views` 为页面，`components` 为附件、卡片、选择器，`api.ts` 为请求处理，`model.ts` 为字段/持久化适配层，`store.ts` 为账号、字典与列表缓存。构建产物位于 `static/mobile`，独立于电脑端静态资源。

在项目根目录运行：

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend test
pnpm --dir frontend build
.venv/Scripts/python.exe -m unittest discover -s tests -p test_mobile_api.py -v
```

开发可用 `pnpm --dir frontend dev`，Vite 将 API/上传地址代理到本地 5050。修改源码后须重新 build 才会更新 Flask 的 `/m/`。

## 数据与异常处理

金额提交十进制字符串，空可选金额提交 null。已有附件采用原始存储地址，临时签名仅用于预览，不写回数据库。编辑仅发送本页面管理的字段；原附件未变则省略附件字段，付款始终省略发票关联字段。

登录过期弹出重新登录界面，保留内存表单；有已登录账号时限制使用原账号恢复。网络失败保留表单，不自动重试写请求；结果不确定时禁止再次保存并要求刷新列表核对。手动刷新/关闭网页仍会丢失未保存表单，不提供离线草稿。

接口兼容扩展、附件事务处理和测试细节见 [MOBILE_BACKEND.md](MOBILE_BACKEND.md)。数据库模型字段和表结构未变。未执行初始化、迁移或生产数据操作。

## 本地验证记录

2026-09-24：前端 16 项测试、后端 11 项测试、TypeScript 检查及 Vite 构建通过。覆盖金额适配、首次打开选择器、登录过期事件、写请求不自动重试、附件失败重试、中文名保留、三模块新增编辑、关联筛选、原附件/发票保留、同秒中文文件上传不覆盖和 schema 前后相同。

浏览器使用现有 SQLite 的临时副本（5051），实际验证登录、新增项目→订单→付款、联系人自动带出、付款编辑（空开票金额）、中文 PNG/PDF 文件选择上传及保存后详情跳转。正式本地实例保持 6 项目、18 订单、12 付款；测试副本新增的验收数据未写入正式本地实例。副本与原库 24 张表结构一致。电脑后台首页也读取到副本中的 19 笔订单、13 笔付款，确认手机新增记录进入同一业务数据源。

360、390、430px 详情页检查均无横向溢出，390px 首页已视觉检查。手机宽度检查使用桌面浏览器 viewport，不等同于真机验收。Android Chrome、iPhone Safari 的实际拍照/相册/文件选择、软键盘、HEIC 预览仍须用真实设备验证。阿里云代码、HTTPS、反向代理上传限制和私有 OSS 实际签名访问尚未检查。

## 发布与撤回

本期仅交付本地版本。发布前备份现有应用代码与静态资源，核对部署端 API、依赖版本、JWT 约定、HTTPS、上传目录/权限、OSS 配置及代理文件大小限制。前端源码不需要在服务器上运行 Node，部署已构建的 `static/mobile` 即可。

只更新兼容后端代码、模板切换链接和手机静态资源；不要运行含删表逻辑的数据库初始化命令或自动迁移。建议先在测试环境验证现有电脑表单和上传流程。

撤回手机入口时恢复电脑模板切换链接及 `/m/` 路由、撤回 `static/mobile`，继续保留电脑 `/` 入口；兼容 API 扩展可保留。不要删除业务数据、已有上传文件或数据库表。
